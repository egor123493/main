# Архитектура

```text
Пользователь / сохранение файла
              |
              v
      extension.ts (activate)
              |
      +-------+--------+
      |                |
      v                v
Команды VS Code   onDidSaveTextDocument
      |                |
      +-------+--------+
              v
       analyzeDocument(document)
              |
              v
          analyze(source)
              |
  +-----------+------------+
  |                        |
  v                        v
Удаление комментариев   Map<глубина, строка>
и строковых литералов       для return/throw/
  |                         break/continue
  +-----------+------------+
              v
  Массив FunctionInfo и регулярный поиск вызовов
              |
              v
   Массив Issue { строка, столбец, текст, код }
              |
              v
 VS Code DiagnosticCollection -> панель Problems
```

## Компоненты

- `activate` регистрирует команды, событие сохранения и хранилище диагностик.
- `analyzeWorkspace` находит C/C++ файлы средствами API workspace.
- `analyze` реализует правила анализа. `Map<number, number>` хранит глубину блока и наличие безусловного завершения управления; массив `FunctionInfo` хранит найденные `static`-функции.
- `DiagnosticCollection` связывает результаты с конкретным документом и позволяет VS Code подчеркнуть строку.

## Алгоритм

Сначала из копии текста маскируются комментарии и строковые литералы, чтобы ключевые слова в них не влияли на результат. Затем текст просматривается построчно: поддерживается счётчик вложенности фигурных скобок и карта завершённых блоков. Если после `return`/`throw`/`break`/`continue` в том же блоке встречается исполняемая строка, создаётся диагностика. Во время того же прохода собираются определения `static`-функций. Для каждой функции считается число конструкций `имя(` в исходном тексте: одно совпадение означает, что найдена только декларация, а вызова нет.
